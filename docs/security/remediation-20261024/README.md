## What the local bypass test actually found

The fixture runs the candidate Worker and container with a local-only R2 checkpoint.
All Worker-originated external fetches are replaced by the existing synthetic ALS,
Plate.hk and SeeHouse fixtures; every other external fetch is denied by the harness.
An ephemeral sentinel, with no host ports or volumes, has HTTP listeners on 80 and
23456. An unrestricted control reaches it successfully. A process inside the app
container then reaches both listeners and opens raw TCP on 23456, causing two
unexpected HTTP effects. Direct backend reads with absent/forged credentials are
403. The DNS lookup test also resolves a name outside the gateway-host contract;
that result alone does not prove a public DNS query escaped.

The direct-sentinel bypass survived a fresh local runtime/image start, explicit
`enableInternet = false`, an outbound catch-all deny handler and HTTPS interception.
This demonstrates **failed local isolation acceptance**, not a production exploit.
The SDK is pinned to 0.3.7 (also the latest observed version); Wrangler was updated
from 4.143.0 to 4.152.0 because the earlier workerd could not run the repository's
existing compatibility date. Keep the failed receipt. Do not count policy declarations
or mocked gateway tests as evidence that raw/direct egress is contained.

## Edge design and remaining gates

Public and optional authenticated reads share the controller's admission quotas.
Before container dispatch, an atomic SQLite transaction reserves one operation's
full call and byte allocation, subject to daily and concurrent-operation ceilings.
A random grant is installed by the trusted controller after stripping caller-supplied
internal headers. The backend claims it once through `http://mcp-egress/claim`.
Every adapter fetch then uses the same internal gateway; redirects and retries are
separate attempts. The grant is invalidated when the response finishes or is cancelled.
Expired, cancelled, in-flight or uncertain work retains its unused reservation.

The Worker gateway permits no caller cookies/auth/accounting headers to the source.
A configured curated backend gets only its own scoped credential at its exact origin
and `/v1/` path. Bootstrap reads the accepted R2 object internally; it does not get
an arbitrary source-fetch exception. There is no application direct-egress fallback.
The intended platform boundary denies direct HTTP/HTTPS, raw TCP and public DNS;
its local runtime acceptance is currently failing as described above.

Candidate public allocation: 100 HTTP attempts, 8,000,000 decoded body bytes,
30 seconds including streaming, two simultaneous fetches. Maintenance is separately
bounded at 2,000 attempts, 1,000,000,000 decoded bytes, 900 seconds, six fetches.
Candidate shared daily envelope: 500,000 attempts and 8,000,000,000 decoded bytes.
These values are **proposed release settings**, not owner-approved cost limits,
bill estimates, production guarantees or representative validation of every adapter.
A partially observed terminal chunk is recorded even if it exceeds a byte allocation;
it triggers cancellation. DNS lookups/TLS handshakes are not HTTP attempt counts.
Application response bytes remain separately named in usage reports.

## H1–H6

- H1: the unlocked installer is retired; it prints the locked procedure and installs
  nothing. The isolated environment was installed from the repository locks.
- H2: the upstream-identity fork publishing guard is unchanged. Publishing remains
  disabled; no registry operation was performed.
- H3: `mcp-hk-http` already defaults to `127.0.0.1`. For Docker bind the host port
  explicitly: `-p 127.0.0.1:8000:8000`. Public serving requires a configured reverse
  proxy, host/origin policy and quotas. Unauthorized operator routes are tested.
- H4: serving SQL is application-generated and parameterized; required features
  include JSON functions, schema creation, WAL and snapshot maintenance. `Store`
  connections now deny ATTACH/DETACH and runtime `load_extension`; required JSON
  operations and the existing restore/maintenance suite remain covered. No SQL
  injection or universal restriction of offline database tools is claimed.
- H5: admission remains synchronous without a new await between check/update;
  the existing focused quota tests plus concurrent operation reservation tests apply.
- H6: operator body reads now have whole-body deadlines and size cancellation;
  the operator source relay is also bounded. Unauthorized calls do no source work.
  Data checkpoint limits and separate auth storage are preserved.
